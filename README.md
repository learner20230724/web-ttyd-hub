# Web TTYd Hub · 随时接着干的浏览器终端

[English](README_EN.md) · [复制粘贴指南](docs/clipboard.md) · [部署指南](docs/deployment.md) · [AI 可读摘要](llms.txt)

**电脑开工，手机接手。关掉网页，任务继续。**

基于 **ttyd + tmux** 的自托管 Web 终端会话管理器：在浏览器中创建、切换、停止和重连多个终端，让远程开发、日志排查和命令行 AI 编程工具随手可用。本仓库是 [sosopop/web-ttyd-hub](https://github.com/sosopop/web-ttyd-hub) 的改进版，使用官方 ttyd，无需修改 ttyd 内核。

## 解决什么痛点？

| 你遇到的问题 | 这里的处理方式 |
| --- | --- |
| 多终端要记不同端口、手动启动进程 | 网页创建命名会话，侧栏切换，统一 HTTP / WebSocket 入口 |
| 关网页后担心长任务断掉 | tmux 承载任务，浏览器断开后可重新连接 |
| 手机与电脑之间来回切换 | 响应式页面，同一会话可从多个浏览器访问 |
| 拖选被 tmux 抢走，复制日志很费劲 | 桌面直接操作活动窗格，浏览器本地拖选；应用鼠标模式下可用 Shift+拖选 |
| 输出太多，难找之前的日志 | 桌面终端原生回滚 20,000 行，并恢复 tmux 已保留历史 |
| 调整窗口时提示干扰操作 | 关闭 ttyd 离开确认与尺寸浮层 |
| 部署需要重新拼配置 | 提供回环监听、Caddy HTTPS/认证与 systemd 示例 |

## 和官方 ttyd、上游 Hub 的关系

[官方 ttyd](https://github.com/tsl0922/ttyd) 提供浏览器终端能力，tmux 提供会话保活。上游 Hub 已提供 Vue 管理界面、多会话、Shell 选择和统一代理。

本改进版提供桌面 xterm.js 终端数据通道、独立滚动与历史恢复、手机阅读界面、会话持久化与归档等功能。ttyd 仅监听回环地址，原终端代理保留兼容；无需修改官方 ttyd 或 tmux。复制粘贴依赖终端与浏览器能力，没有跨设备剪贴板同步。

## 在终端中直接滚动

桌面端现在使用 **xterm.js + tmux control mode**，在同一个终端里连续浏览历史与实时输出，独立「历史输出」按钮和预览面板已移除。每个浏览器有自己的滚动位置，不进入共享的 tmux copy mode，不把滚轮变成上下键；上翻时新输出继续接收，输入或粘贴会回到底部。

首次连接、刷新和断线重连时，从 tmux 恢复最多 20,000 行保留的历史及当前屏幕，再持续接收活动窗格的原始输出。ANSI 颜色、中文输入法、选择复制和多行括号粘贴都在终端内完成；粘贴不会额外发送回车。手机继续使用独立的回答/全文阅读界面，不调整电脑窗格尺寸。

全屏程序保留自己的备用屏幕和鼠标交互；退出后回到正常历史。浏览器滚动互相独立，但在同一个进程内操作编辑器、切换应用页面仍会共享状态，实际终端列数也仍由 tmux 的窗口尺寸策略决定。已被 tmux 丢弃或被应用覆盖的内容无法恢复。技术说明与验证步骤见 [终端数据通道](docs/terminal-stream.md)。

## 新建 Codex 或普通终端

Windows 和 Linux 均支持先选项目，再选择 **新建空白会话** 或 **恢复历史会话**。历史列表支持标题/ID 搜索、分页和最近对话预览；恢复时在对应项目中运行 `codex resume <会话ID> --yolo`，已有 Hub 终端会优先复用。Linux 纯 CLI 安装也能从本机 Codex 历史中发现项目，不需要桌面版。详见 [项目与历史会话选择](docs/codex-history.md)。

新建会话的终端类型默认选择 **Codex**，创建后在 tmux 中自动运行 `codex --yolo`；也可选择 Bash、Zsh 等普通终端。服务器需已安装并配置 Codex，且 `codex` 在 Hub 服务的 PATH 中。退出 Codex 后回到普通 shell；刷新、切换客户端或重启 Hub 会重新连接已有 tmux，不重复输入启动命令。`POST /api/sessions` 可传 `shell: "codex"`，已有普通终端的类型保持不变。

Codex 启动前会经过交互式 shell 初始化，继承普通终端启动文件里的代理等环境设置；项目不内置代理地址，也不修改机器上的代理配置。

## 会话排序与置顶

拖动会话左侧的 **⠿** 调整上下顺序，手机也可按住手柄拖动。点击图钉按钮置顶，再点一次取消；置顶会话始终在最上方，置顶组和普通组分别排序。键盘用户可聚焦拖动手柄后按上下键排序，拖动中按 Esc 取消。

顺序、置顶和已读状态统一保存在 Hub 服务器，手机 APP、手机浏览器和电脑实时同步，刷新和 Hub 重启后保留。首次升级会接续已有本机已读记录，排列以最先连接设备的旧设置初始化，随后以服务器为准。排序和置顶不会切换当前会话或重建终端连接。

## 中文名称与重命名

创建时可输入中文、空格和常见符号，例如「项目开发」「日志排查 第二轮」。名称去除首尾空格，长度为 1–80 个字符，不接受重复名称或控制字符；留空自动命名。

在侧栏点击会话右侧的 **✎**，输入新名称并保存；支持 Enter 保存、Esc 取消，中文输入法选词回车不会触发保存。运行中和已停止的会话都可以改名。显示名称与内部 ID 分离，重命名不会重建终端或中断任务，其他浏览器同步显示新名称。

API：`POST /api/sessions` 的 `name` 是显示名称；响应 `name` 是稳定内部 ID，`displayName` 是界面名称。`PATCH /api/sessions/:name` 使用稳定 ID 寻址，请求体为 `{"name":"新的中文名称"}`。旧 ASCII 会话 ID 保持兼容。显示名称与稳定 ID 一起持久保存，Hub 重启后恢复并重新接续 tmux。

验证：`npm test`（需要 ttyd 和 tmux）以及 `npm run build`。

## 复制粘贴：把容易踩的坑讲明白

- **复制**：拖选终端文字，使用浏览器复制菜单或系统快捷键。Windows/Linux 常用 `Ctrl+Shift+C`，macOS 常用 `⌘C`，取决于浏览器。
- **粘贴**：先点进终端，再用 `Ctrl+Shift+V`、`⌘V` 或浏览器粘贴菜单。`Ctrl+C` 无选区时通常是中断任务。
- **选不中**：检查 tmux 鼠标捕获；可选配置使用 `set -g mouse off`。应用自身开启鼠标模式时，桌面浏览器可尝试按住 Shift 拖选。
- **手机与权限**：长按菜单、软键盘和剪贴板权限受浏览器限制，不承诺所有机型表现一致。公网部署使用 HTTPS。

完整操作与历史输出说明见 [复制粘贴指南](docs/clipboard.md)。

## 快速开始

需要 **Node.js 22.12+、npm、ttyd（支持 `-W`）、tmux 3.4+**，Linux 或 macOS。Windows 可使用 WSL，原生 Windows 未验证。

```bash
# Ubuntu / Debian；macOS 使用 brew install ttyd tmux
sudo apt install ttyd tmux
git clone https://github.com/learner20230724/web-ttyd-hub.git
cd web-ttyd-hub
npm ci --include=dev
npm ci --prefix frontend --include=dev
cp .env.example .env
npm run build
npm start
```

打开 `http://localhost:3000`，创建第一个会话。示例只允许本机访问，远程使用见 [部署指南](docs/deployment.md)。开发运行 `npm run dev`，前端端口 5173，后端 3000。

## 使用边界

- 浏览器断开后保活**不等于机器重启后恢复**。会话列表持久保存，Hub 重启重新连接仍存活的 tmux；机器重启不能复活已结束的进程。
- 停止会话关闭接入，保留 tmux 任务；删除先归档 30 分钟，归档到期或永久删除才结束任务。
- 多浏览器共享同一操作环境，**没有内置账号系统、用户隔离或细粒度权限**。访问者拥有服务系统用户的权限；对外开放须配置认证和 HTTPS。
- 浏览器回滚与 tmux 历史是两套机制。机器重启、进程退出或使用 systemd 默认进程组清理都可能终止任务。

## 手机阅读与 Codex 状态（Android 1.1）

手机不再缩小电脑上的共享 tmux 窗口：独立聊天阅读界面支持 Markdown、代码块、彩色终端回退、原生滑动和长按复制。底部中文输入框支持系统粘贴、多行编辑与发送。APK 移除了顶部键盘/粘贴工具栏。

会话列表和手机标题使用同一套状态文字，区分工作、思考、回复和执行；列表中以蓝色转圈提示工作中，手机标题后只保留工作状态文字。黄色表示等待你操作，绿色表示成功完成但未读，红色表示出错，另有中断和状态待确认提示。已读后显示「已完成 · 已读」，已读标记按设备保存。只有明确的成功 turn 结束事件才产生绿色提醒；中途回复、工具执行完、静默、中断和失败都不算成功完成。

Linux 同时兼容独立 Codex 进程和 0.162.1 的共享后台：通过终端进程的 Unix socket 确定后台，只在该后台实际打开的主任务记录中，用当前完整终端标题与项目名唯一匹配。子任务不参与匹配；同名歧义、标题不可用、进程退出或读取失败时显示「状态待确认」，不按最近修改时间或旧 thread ID 猜测。共享后台适配需要 `ss`（通常由 iproute2 提供）、Node 的只读 SQLite 支持以及读取本用户进程的权限；不修改 Codex 配置。Windows 保留独立进程记录适配；Windows 的共享后台尚未验证。

手机将状态紧接在会话标题后，同一行显示；长标题省略，完整名称可在会话列表查看，较宽屏幕另显示本轮用时。状态暂不可用或连接中断时只保留标题旁的简短状态，不额外显示占用阅读空间的说明和全文按钮；内容读取与状态识别独立。工作进展与回复分别标注；需要确认时可一键打开全文和方向键。回到前台、网络恢复以及前台定期同步都会核对状态，断线时显示连接中断并保留草稿。适配 320px 小屏和安全区域，网页/APP 页面在线更新。

手机顶部标题右侧的绿色圆形数字显示其他会话中「已完成但未读」的数量，始终排除当前选中的会话和归档会话；为 0 时隐藏。点击绿色数字直接打开列表排序中最上方的未读会话，沿用置顶和手动排序，连续点击可依次查看，读完自动隐藏。状态变化实时更新，连接恢复时重新读取最新状态。

绿色数字旁的灰色旋转圆环显示其他正在工作的会话数量，包括工作、思考、回复、执行和重试；与绿色数字一样，始终排除当前选中的会话，切换后立即重新计算。等待操作、已停止、已归档的会话不计入。为 0 或连接中断时隐藏，数字本身不旋转；系统选择减少动态效果时，圆环保持静止。

灰色数字也可点击：按当前列表的置顶和排列顺序，跳到下一个工作中的会话，到末尾后回到第一个。例如三个会话 A → B → C → A 依次循环，不会只在前两个之间跳转。当前不在工作中的会话时，先打开列表最上方的工作会话；已完成、等待操作、已停止或归档的会话自动跳过，切换保留各会话的输入草稿。

### 账号额度与手机追问

会话菜单底部的「账号额度」显示服务器上 Codex 当前登录账号的剩余比例、额度周期和重置时间，各会话共享同一账号额度。只展示 Codex 实际提供的账号限额，不用会话 Token 数或反代调用统计推算。打开时读取，支持手动刷新；读取失败会标记上次成功数据的时间，未提供的数据不显示成 0。到达重置时间后仍需向 Codex 刷新确认，不在本地自动补满。

新版 Linux 共享后台会将尚未回答的 Codex 追问显示在手机输入框上方。点「回答追问」可选择选项、自行填写或补充，多题一起提交；点「跳过追问」将本次问题留空，继续原任务，不发送 Esc 或中断命令。提交后等待后台确认；电脑端已处理、会话切换、问题结束或连接断开时不继续提交过期问题。收起或切换会话保留本次网页内的追问草稿和原消息草稿；刷新网页后追问草稿不保留。

直接回答需要当前终端与 Codex 共享后台唯一关联，已验证 Codex 0.162.1。旧版独立进程、Windows 或不能确认关联的会话，继续使用「查看全文」及方向键/回车，按终端自身提示回答或跳过。既有任务无需重启；不为新功能终止旧版会话，也不修改全局 Codex 配置。

## 会话恢复与动态排序

Hub 自动保存稳定会话 ID、中文显示名、shell、创建时间、运行/停止状态，以及检测到的 Codex thread ID。默认文件是 `data/sessions.json`，可用 `HUB_STATE_FILE` 指定独立路径；原子替换、权限 0600，同时保留上一份 `.bak`。该目录已排除 Git，迁移时单独备份，不能放进公开仓库。服务启动自动恢复名称和列表并重新连接已有 tmux；保留 `KillMode=process`，重启 Hub 不终止任务。状态文件损坏时拒绝启动和覆盖，请人工核对并从 `.bak` 恢复。整台机器重启后只能恢复会话列表，不能复活丢失的进程；记录的 Codex thread ID 可用于手动恢复对话。

会话列表按置顶分组，组内按「等待操作／出错 → 完成未读 → 工作中 → 已读／空闲」实时排序。绿色会话在前台打开后，各设备一起变灰，并移到所属置顶/普通分组的灰色会话最上方；正在前台查看的任务完成时也按此规则归位。重复点击已读会话或刷新状态不会再次挪动，其他同状态会话保留拖动顺序。已读标记对应具体一轮回复，旧设备延迟送达的标记不会将新回复误标已读。网络恢复时自动核对状态，失败的同步操作在当前标签页／WebView 内重试，刷新页面后仍可继续。当前打开的会话、草稿、滚动位置和阅读字号仍由各设备独立保留。手机阅读字号支持 4–24 px，在线更新无需新 APK。

网页与 APP 会在本机记住最后打开的会话，下次进入时，在成功读取列表后自动回到该会话。记录使用稳定 ID 与创建时间，改名不影响恢复；已归档、删除或同名重建的旧会话不自动打开，手机会展开列表供选择。停止的会话仅恢复选中，不自动启动。不同浏览器和 APP 各自保存选择，已打开的标签页不会被其他标签页强制切换。

## 归档保护与手机快捷操作

普通删除现在移入侧栏底部归档：原进程继续运行，保留 30 分钟。期间可恢复，归档中再次明确选择彻底删除才立即终止任务；到期自动清理，重启不重新计时。`DELETE /api/sessions/:name` 为归档，`POST /:name/restore` 恢复，`DELETE /:name/permanent` 仅允许删除已归档会话。旧版客户端的删除请求也受到归档保护。

会话卡片仅显示一个「⋯」操作菜单，名称以 12px 完整换行。手机顶部「✥」控制常驻的七键面板（↑ ↓ ← → ↵ Shift+← ESC），连续按键不会收起，面板按键不发送草稿。以上功能在线更新，无需新的 APK。

手机回答/全文分别缓存，访问会话时预读另一视图，切换先显示本机内容再后台更新。已访问内容保存在 IndexedDB，刷新后可复用，滚动位置在本次使用期间按会话和视图保留。内容未变化时服务器返回 304，减少长记录的重复传输；Markdown 和 ANSI 渲染结果也会复用。缓存有容量上限，删除会话后同步清理，只保留服务端已提供的历史窗口，不能替代服务器备份或离线终端。
