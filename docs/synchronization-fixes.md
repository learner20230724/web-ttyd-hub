# 会话同步修复与验证（2026-11-08）

## 数据边界

- 内容缓存由终端 ID、创建时间、当前 Codex thread 和视图共同定位。当前 thread 优先于首次启动的 resume ID；恢复历史时不再复用已经切到别的 thread 的终端。
- 回答只渲染结构化对话；全文只显示终端输出。结构化来源暂不可用时显示同步状态并自动重试，不把终端内容伪装成回答，不用旧 thread 的缓存补位。
- 已读必须匹配实际渲染的 completion 与 contentRevision。Windows iframe 的 load 不构成已读凭据；Windows 用户可在聊天记录视图确认已读。
- 重命名、停止、重启、归档、恢复和永久删除要求创建时间校验；客户端同时提交当前 thread。队列输入也在粘贴、回车前重新核对身份。
- 排序和置顶使用持久操作 ID，服务端保存去重账本，重试不会再次覆盖另一个设备的后续排序。操作有效期 7 天；不静默重放过期操作。
- 待同步状态下，徽标、计数、排序使用同一份最近确认状态；它们不构成新内容已读的证据。

## 输入与历史

- 发送成功仅表示终端已接收。Codex 接收确认还需同一 thread 中、服务端接收时间之后的匹配用户消息或问题回答记录；没有可信边界时保留未确认状态，不用旧的相同文字消除提示。
- 草稿文字和已上传图片引用按完整对话身份保存在本浏览器站点存储中，保留最近 100 份。不会跨设备自动同步；浏览器清理或禁止存储时不能保证持久化。
- 生命周期写请求的响应头和正文均有 15 秒期限；超时不会自动重发。图片上传为 60 秒，终端图片输入确认 15 秒。
- 在线对话仍保留最近 300 条，用户可逐页加载更早消息，每页最多 300 条。游标绑定当前会话，读取期间文件替换或截断会拒绝结果。终端缓冲仍有保留上限；Linux 全文超过 20,000 行时显示截断状态，不声称能恢复已被 tmux 丢弃的历史。
- 页面检测服务器版本变化后提供“更新”，由用户点击刷新；更新前保存草稿，不在编辑中强制刷新。现有 Android 外壳继续加载同一在线页面，无需新 APK。

## 验证方法

以隔离 tmux、合成 rollout 和浏览器页面验证，不向用户真实 Codex 会话发送测试输入。

- 单元/接口：`npm test`，包括历史恢复目标、同名会话与同终端换 thread、旧版本已读、排序重试与重启后去重、650 条消息分页、历史同文输入误确认。
- 缺陷回归：`node tests/audit-regressions-browser.cjs`，360px 手机与 1280px 桌面，包含来源断开、草稿重载、换 thread、回答/全文切换、永不返回的修改名称请求。
- 消融：停用通知通道、挂起响应头/正文、只提供旧磁盘缓存、漏发前台事件，分别验证独立 HTTP 协调与定时恢复。相关脚本为 `state-refresh-ablation-browser.cjs`、`mobile-answer-convergence-browser.cjs`、`mobile-lifecycle-browser.cjs`。
- 不把模拟移动视口写成 M153 真机验证；本次没有连接手机或 Windows 真机。

发布沿用 `npm run deploy:web`，保留原有 tmux pane/PID 和最近版本资源。旧页面首次需刷新以加载本次版本；之后版本差异可由页面“更新”按钮提示。
